# self-reflection — 会话自省与改进闭环流程

## 输入

- 会话 transcript：`.claude/sessions/<id>.jsonl`（SessionEnd hook 自动镜像；无归档时从 `~/.claude/projects/` 对应项目目录手动复制）

## 步骤

1. **读 transcript**：找用户 prompt（真实指令，剔除 tool_result 与 `<` 开头的系统注入）与关键 tool 调用时间线。

2. **提炼修正模式**——五类信号：

   | 信号          | 数据特征                                  | 含义                     |
   | ------------- | ----------------------------------------- | ------------------------ |
   | 重复指令      | 同一意图 prompt 出现 ≥2 次                | 第一次没做对             |
   | 术语/概念纠正 | prompt 含"不要 X 应该 Y"式表述            | 概念漂移，需术语铁律     |
   | 架构/边界裁定 | prompt 涉及目录归属/什么不是什么          | 边界未定义或被违反       |
   | 返工循环      | 同一文件被反复编辑 ≥3 次                  | 方案错了，非实现错       |
   | 纪律违规      | 我做了红线明令禁止的事                    | 规则未生效，考虑转 hook  |

3. **定级处置**：

   | 模式出现次数 | 处置                                       |
   | ------------ | ------------------------------------------ |
   | ≥2 次        | Miss→Rule 候选：提议进 rules/skill/hook    |
   | 1 次但重大   | ADR 候选（经用户确认）                     |
   | 1 次普通     | memory 记录，观察                          |

   关键判据：**advisory 规则被违反 ≥2 次 → 转 hook 强制**（rules 无强制力，先例 Claude Code issue #34132 官方确认）。

4. **汇报**：模式表 + 晋级候选 + 证据（prompt 原文引用），请用户裁决；确认后写入对应资产并同步更新。

## 纪律

- 自省产物是候选，不是结论——未经用户确认不写 rules/skills/REVIEW.md
- 只看增量：同窗口二次自省只分析上次之后的新会话
- 不把任务性细节（在做什么功能）当模式；模式是"怎么做"的修正，不是"做什么"
